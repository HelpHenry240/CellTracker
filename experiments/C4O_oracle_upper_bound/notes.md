# C4O Oracle 实例上界：前端实例化到底值多少分

## 问题

AOGM 分解显示 A（真实检测档）的损失里，前端相关约占 70%（NS 多余分裂操作 43%、
FP 假阳性 9.5%、EA 缺失边约一半）。但"前端还能拿回多少分"一直没有量化。
本实验给出这个**上界**：保留 nnU-Net 掩码（体素级分割）不变，只把
"哪个体素属于哪个实例"替换成**完美分配**（用 GT `_GT/TRA` 标记作分水岭种子），
其余链路（OT → 式(26) 候选 → GNN → 重建 → 官方评测）完全不变。

> ⚠️ 这是**作弊设定**：种子来自真值。它的唯一用途是给出"前端实例化"这条路线
> 的收益上限，**不代表任何可部署的方法**。

## 实现

给 `split_instances` 增加 `seeds=` 参数（给了 seeds 就跳过 h-maxima，
直接 marker-controlled watershed）；`predict_to_h5.py` 增加 `--oracle-markers`
与 `--unseeded-policy`。三个工程细节都按预设处理：

1. **种子落在掩码外** → 不产生实例（如实计入缺失，不补）；
2. **掩码内无种子的连通域** → `drop`（本轮口径；`keep_component` 作为备选未跑）；
3. **标记是等体积小点**（与核体积约 1:23）→ 直接以标记体素为种子，不做膨胀。

新增 3 项单测覆盖上述语义（外部种子切分、掩码外种子不产生实例、两种 unseeded 口径）。

## 结论（这是本次最关键的判断依据）

1. **前端实例化的收益上限 ≈ +0.079 TRA**（0.9057 → 0.9848）。
   相比追踪侧的任何改动（top-k 扩容 +0.0008、消融里最大的 GNN 项 −0.0034），
   高一个数量级。**用户的判断成立：剩余分数主要压在前端实例化上。**
2. 误差构成印证同一结论：oracle 把 **FP 2456 → 9**（270×）、**NS 2199 → 211**（10×），
   但 SEG 只从 0.6732 升到 0.6887 —— 说明**掩码体素质量不是瓶颈，实例归属才是**。
   （SEG 变化小也说明：靠"让掩码更准"是拿不到分的，必须改实例化。）
3. oracle 与 GT 标记上界之间只剩 0.0118 的差距，这部分是 nnU-Net 掩码本身的
   覆盖缺口（U0 0.988 → 1.0）与残余边界误差——属于"训练分割网络"的范畴，
   与实例化是两件事。
4. 因此 Distance/Boundary Head（C5.2）**值得做**：它正好瞄准"从掩码里恢复实例"
   这一环，且我们已验证该信号在图像中可见（同一实例内相邻细胞对中，
   77.3% 的中点比两端更暗）。

## 下一步

1. 零重训的低成本尝试先做（可能吃掉一部分收益）：对体积异常实例用 EDT 峰再切、
   孤立短轨迹过滤；
2. 之后按 C5.2 规划 Distance Head（预计 7.4h 训练 + 1–2 天开发），
   用本实验的 0.9848 作为收益上限、0.9057 作为起点；
3. 不要在追踪侧继续调参——那里可挖的空间已被本实验封顶（≤0.012）。
