# C1 nnU-Net 推理（CE seq01 + seq02，385 帧）

## 目的

把 E5.1 训练好的 3D nnU-Net（验证 Dice 0.9605）接到链路最前端：对 CTC
`Fluo-N3DH-CE` 两个序列的**有标注帧**推理，产出语义掩码，供 C2 拆实例、
C3 转成内部检测 h5。这是"三档检测来源"里**真实前端档**的数据基础。

## 做了什么

| 项 | 值 |
| --- | --- |
| 云端 GPU | RTX 4090 24GB，利用率 100% |
| 数据集 / 配置 | `Dataset501_CellTrackerCE` / `3d_fullres` / fold 0 |
| 权重 | `checkpoint_best`（训练期最优，验证 Dice 0.9605） |
| TTA | 默认开启 |
| 体素间距 | `(0.09, 0.09, 1.0) µm`（与训练一致，否则重采样决策会错） |
| 帧数 | 385（seq01 195 + seq02 190） |
| 耗时 | 约 36 分钟 |
| 产物 | `data/interim/preds_nnunet/`（385 × `*.nii.gz`，33MB，已下载） |

## 观察（数字/现象）

- 单帧输出形状 `(35, 512, 708)`，与 GT 标记/原图同形，可直接进入下游。
- 语义层面质量高：训练验证 Dice **0.9605**；前景体素随胚胎发育增长
  （seq01 首帧 1.7e5 → 末帧 1.3e6 体素）。
- **实例层面不成立**（C2 的结论）：把语义掩码拆成实例后，平均
  **50.4 实例/帧 vs 122.1 GT 标记**（= 0.41 实例/标记），末 50 帧只有 0.32，
  即每个"实例"平均覆盖 3 个细胞。见 `figures/instances_vs_markers.png`。

## 留痕说明（诚实记录）

1. 推理当时是在云端直接跑命令行，**没有把命令与日志落盘到实验目录**——
   这是本目录 09-20 才补建的原因（C0）。`command.sh` 中的命令是**按产物命名
   与 `scripts/nnunet/*` 回填的等效命令**，C4 开机后与云端 shell 历史核对，
   并把 `predict.log` 补进 `logs/`。
2. `data/interim/pred_report_01.json` 的 `aggregate.config` 记录为
   `min_distance=6, min_volume=100`，但实测部署配置是 **`h_frac=0.35`**（自适应
   h-maxima 种子，此时 `min_distance` 不生效）。这是**标定配置与部署配置不一致**
   的事故，详见 `experiments/C2_instance_split/notes.md`；h5 的 attrs 已于 09-20
   回填 `h_frac=0.35` 并加注说明，`predict_to_h5.py` 也已补 `--h-frac` 入口与
   attrs 记录（脚本层修复），并补了回归测试。

## 结论

推理链路可用、产物完整，可进入 C2/C3。前端**语义质量高但实例质量差**，
瓶颈定位在"语义 → 实例"，这直接决定了 C4 全链路数字的天花板与 C5 的方向。
