# E1.1 经典基线：匈牙利匹配（GT 检测上界设定）

## 目的

建立 Phase 1 的参考基线，并打通"追踪 → CTC 提交 → 云端官方评测"的完整链路。

## 设定（重要口径）

- **检测来源**：CTC 金标准 `_GT/TRA`。
- **关键事实（本实验发现）**：CTC 的 **TRA 标注是"标记点(marker)"而非完整细胞分割**
  （Fluo-N3DH-CHO seq01 某帧：marker 5171 体素 vs 银标准 ST 全分割 117035 体素；
  marker 100% 被 ST 覆盖）。因此把 marker 重新着色作为结果掩码时，
  官方评测 **DET 仍为 1.0**（匹配规则基于参考目标的覆盖率），而 **SEG 不具意义**
  （marker vs 金标准全分割，SEG≈0）→ SEG 一律留到 Phase 5 用真实分割报告。
- **另一发现**：Fluo-N3DH-CHO 的 TRA 标记**全部位于 z=0 切片**，该数据集标注实质是 2D；
  真正的 3D 难点集是 **Fluo-N3DH-CE**（主力）。

## 做了什么

1. `src/celltracker/track/base.py`：检测器接口 + 连接器（贪心 / 匈牙利）+ 匀速先验 +
   二分裂判定（一个消失的父 + 两个邻近新生）。
2. `scripts/run_baseline.py`：检测 → 连接 → 画掩码 → 写 `01_RES` → 本地诊断 →
   云端官方 DET/SEG/TRA → 出图 + 记录。
3. `scripts/cloud_eval.py`：上传结果 → 云端跑 `SEGMeasure/DETMeasure/TRAMeasure` →
   回传指标与官方日志（含逐条错误边）。

## 观察（Fluo-N3DH-CHO seq 01，92 帧）

| 方法 | 预测轨迹数 | DET（官方） | TRA（官方） | 本地 FN/FP | ID switch | 碎片化 |
| --- | --- | --- | --- | --- | --- | --- |
| 匈牙利 | 27 | **1.000000** | **0.998555** | 0 / 0 | 0 | 0 |
| 贪心最近邻 | 27 | 1.000000 | 0.998555 | 0 / 0 | 0 | 0 |
| 匈牙利+匀速先验 | 27 | 1.000000 | 0.998555 | 0 / 0 | 0 | 0 |

金标准：27 条轨迹、10 次分裂。TRA 损失的 0.00145 全部来自**未识别的分裂边**
（官方 `TRA_log.txt` 逐条列出 10 条"Edges To Be Added"，如
`[T=34 GT_label=1] -> [T=38 GT_label=2]`）。注意这 10 个分裂里 7 个跨越较长间隔
（34→38、29→33、30→34…），本实验的分裂判定阈值（45 体素）未能覆盖。

## 结论

- 链路打通：数据 → 追踪 → 提交 → 官方指标 → 图 → 记录，全部可复现。
- **CHO 不具区分度**：三种经典方法指标完全相同（细胞少、标记在单切片、运动慢）。
  方法差异必须在 **Fluo-N3DH-CE**（高密度 3D）上比较——这与计划中"CE 为主力"一致。
- 分裂判定是当前主要失分点（√ 与 §1.6 中"非平衡 OT 处理生死/分裂"的动机一致）。
