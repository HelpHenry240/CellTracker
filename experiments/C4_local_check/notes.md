# C4 本地格式校验（送官方评测前的自检，E2）

## 目的

官方二进制只能报格式错误或指标，不会解释"为什么轨迹被拆碎"。
送官方评测前先在本地跑一遍全链路 + `finalize_tracks` 格式校验与诊断量。

## 做了什么

```bash
python scripts/eval_pipeline.py --h5 data/interim/Fluo-N3DH-CE_01_pred.h5 \
    --gt-h5 data/interim/Fluo-N3DH-CE_01.h5 --dataset Fluo-N3DH-CE --seq 01 \
    --exp-id C4_local_check \
    --ckpt experiments/C4_pred_train/artifacts/model/best.pt
```

## 观察

格式校验通过（轨迹在起止帧内连续、父子关系合法），可送官方评测。诊断量：

| 指标 | GT 检测上界（B1） | **预测检测（C4）** |
| --- | --- | --- |
| 轨迹数 | 755 | **4682** |
| 本地 ID switch | 139 | 16507 |
| 本地碎片化 | 174 | 14463 |
| 分裂 P / R | 0.854 / 0.802 | 0.011 / 0.726 |

## 已知度量局限（必须写明）

1. **本地 FN/FP 对"欠分割"不敏感**：一个大实例覆盖多个 marker 仍算命中，
   所以 FN 仅 47、`detection_precision` 甚至算出 **2.415（>1）**——
   说明该定义在"结果对象少于 GT 对象"时不再成立。
   本地指标只用于方向判断（R4），结论一律以官方 CTC 指标为准；
   这个精度定义为后续可修正项（列入技术债）。
2. **轨迹数膨胀**（4682）说明决策阶段在低质检测上退化：
   GNN 学到的是"实例 id 连续"的模式，而检测层并不提供这种连续性（C4a 的 U2=13.7%）。

## 结论

链路可跑通、格式合法、官方指标可测。但从诊断量看，**全链路 TRA 会显著低于
GT 检测上界（0.9965）**，且学习型决策可能不优于匈牙利——需官方指标确认，
这正是 C4 要如实报告的中间档结论。
