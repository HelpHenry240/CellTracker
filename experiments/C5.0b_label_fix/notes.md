# C5.0b 分裂标签污染修复（gt_parent 空表）

## 怎么发现的

C5.0 的误差漏斗里出现一个说不通的现象：候选集里被标为"分裂"的边有 **5866** 条，
而真实的 GT 分裂边只有 **453** 条（1294%）。顺着查标签生成代码，发现
`src/celltracker/graph/build.py` 的规则：

```python
if gl_s == gl_d:                          labels[k] = MOVE
elif gt_parent.get(gl_d, 0) == gl_s:      labels[k] = DIV
```

预测检测的 h5 **没有 `tracks` 表** → `gt_parent = {}` → `gt_parent.get(gl_d, 0)` 恒为 0。
此时只要源检测未匹配到 GT（假阳性，`gl_s = 0`），条件就退化成 `0 == 0` **成立**，
于是**所有"假阳性源"的候选边都被标成了分裂**；同理 `gl_s == gl_d == 0`
（假阳性↔假阳性）被标成移动。

两个后果：分裂头在垃圾标签上训练；假阳性节点之间被当成真实移动。

## 修复

1. `graph/build.py`：**任一端 `gt_label == 0` 的边一律保持 NONE**
   （它是"不该连"的负样本，这正是论文 §2.0.1 对假阳性的处理方式），
   并补回归测试 `test_false_positive_edges_are_not_labelled_division`。
2. `pipeline/runner.py` + `scripts/run_pipeline.py`：新增 `--gt-h5`，
   从 GT 文件读取 `tracks` 提供分裂血缘；血缘为空时**显式告警**
   （避免"悄悄没有分裂监督"再次发生）。

## 结论

1. **今天找到的两个 bug（C5.0 的 EDT 间距、C5.0b 的分裂标签污染）都是"看不见的错误"**：
   指标不会直接报错，只会让结论变成"这个方法不行"。C4a 当初"GNN 不如匈牙利"
   的判断至少部分由此造成，必须重测（官方指标）。
2. 修复后分裂精确率从 0.011 → **0.489**（44×），碎片再降一半，
   说明分裂头并非"学不会"，而是之前**根本没在真标签上训练**
   （修复后 `support_div` 从 1099 降到 54，是真实的难样本比例）。
3. 剩余瓶颈仍在分裂：事件级 S1 48.2% → S2 29.3%，即**候选生成**（式(26) 规则）
   先丢掉一半分裂事件，其次才是决策。下一步优先级：修式(26) 对分裂子目标的覆盖。
