# A2 相邻帧 OT 阶段接入与消融

## 目的

把 §1.3 的 FGW 结构项（η，式9）与非平衡 OT（τ，式14）**真正接进主链路**，
并给出它们对"交给 GNN 的 OT 先验质量"的量化影响。

## 做了什么

1. **接口层**（`pipeline/config.py`）：论文模块逐段配置 + 统一消融入口
   `apply_ablation(cfg, {"fgw","unbalanced","motion",...})`（不可变语义 + 未知开关报错）。
2. **OT 阶段**（`pipeline/ot_stage.py`）：统一式(8) 特征代价、式(9) FGW、
   式(11)(12) 平衡、式(14) 非平衡、式(22) 运动先验；Γ/C/ε 可落盘复用。
3. **消除重复实现**：`track/ot_tracker.py` 与 `graph/build.py` 都改为调用同一个
   `compute_pairwise_plan`（此前两处各有一套内联求解，口径可能漂移）。
   已验证两条路径（现场求解 / 复用上游 coupling）候选边**完全一致**。
4. **求解器改进**：`sinkhorn_log` 增加**边际违反量判据** `tol_marg`（默认 1e-6）。
   与 POT 对比验证：解最大差 ~1e-6、目标 `<P,C>` 一致到 4 位小数。

## 结果一：候选边覆盖度不受 η/τ 影响

（θ_Γ=0.02、top-k=3、R_max=30，采样帧 60/120/170）

| 配置 | 候选边/帧对 | move 保留 | 分裂保留 | 干扰保留 |
| --- | --- | --- | --- | --- |
| η=0.0 | 430.0 | 1.000 | 0.971 | 0.521 |
| η=0.3 | 430.0 | 1.000 | 0.971 | 0.521 |
| η=0.5 | 430.0 | 1.000 | 0.971 | 0.521 |
| τ=1.0 | 430.0 | 1.000 | 0.971 | 0.521 |
| τ=5.0 | 430.0 | 1.000 | 0.971 | 0.521 |

**结论**：候选边的**选谁**由 `R_max` 与 top-k 保底决定；η/τ 改变的是
**计划的数值**（即交给 GNN 的边特征），而不是候选集合本身。因此 A2 的效果
必须用"先验判别力"来衡量，而不是候选覆盖度。

## 结果二：η 与 τ 对 OT 先验判别力的影响

指标：`AUC(rnorm → 该边是否真实)`、真实/虚假边的平均 rnorm、**argmax 命中率**
（式23 的 argmax 规则本身有多准）。

| 配置 | AUC(rnorm) | 真实边均值 rnorm | 虚假边均值 rnorm | argmax 命中率 |
| --- | --- | --- | --- | --- |
| **η=0（纯特征 OT）** | **0.9931** | 0.8754 | 0.0387 | **0.9573** |
| η=0.3 | 0.9900 | 0.8701 | 0.0406 | 0.9519 |
| η=0.5 | 0.9870 | 0.8675 | 0.0416 | 0.9493 |
| τ=1.0（非平衡） | 0.9873 | 0.8978 | 0.0303 | 0.9533 |
| τ=5.0（接近平衡） | 0.9889 | 0.9003 | 0.0298 | 0.9559 |

**结论**：

1. **FGW 结构项（η>0）在 CE 上略微降低先验判别力**（AUC 0.9931 → 0.9870，
   argmax 命中率 0.9573 → 0.9493）。机制解释：结构项鼓励"保持局部几何"，
   而胚胎细胞密集且运动各异，这会与"位置最匹配"的目标产生冲突。
   注意：这衡量的是**先验本身**，不等于最终追踪更差——最终裁决在 Phase B
   （GNN 可能从更丰富的计划数值中获益）。
2. **非平衡 OT（τ 小）同样略微降低判别力**（0.9931 → 0.9873 @ τ=1），
   τ 增大则趋近平衡解（0.9889 @ τ=5），与式(14) 的理论一致（τ→∞ 退化为平衡 OT）。
   有意思的是非平衡让**真实边的均值上升**（0.875 → 0.900），但 AUC 反而略降，
   说明它提升的是"整体质量水平"而非"区分度"。

## 附加发现（重要）：ε 与决策阈值强耦合

把 ε 从绝对 1.0 换成自适应（≈26.7）后，`ot_tracker` 的 §1.6 手工规则
（"一行两个目标超阈值即分裂"）**严重过分裂**：预测轨迹 693 → **1822**，
碎片化 335 → **1454**。

原因：ε 变大后传输计划变"软"，多行都会出现 ≥2 个超过 `div_ratio` 的目标，
于是到处被判为分裂。这印证了论文的设计逻辑：**计划的职责是"提名候选边 +
提供特征"，分裂判定应当交给 GNN**，而不是靠与 ε 强耦合的手工阈值。

→ 后续（Phase B）训练 GNN 时，决策阈值只在 GNN 的概率空间里调，
不再让 OT 计划的软化程度间接决定分裂数量。

```bash
    --configs "eta=0,0.3,0.5"          # η 扫描

    --configs "eta=0" --tau 1.0        # τ 扫描
```
