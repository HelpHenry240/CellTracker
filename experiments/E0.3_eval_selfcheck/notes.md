# E0.3 评测管线自检

## 目的

评测口径决定所有后续结论的可信度。本实验确认：① 权威指标能算；② 本地快速指标
与权威指标一致。

## 做了什么

1. 下载 CTC 官方评测软件 `EvaluationSoftware.zip`（15.5 MB，含 Linux/Mac/Win 二进制 +
   官方 `testing_dataset` + 说明 PDF）。
2. 本机（WSL2，内核 6.18）运行官方二进制 → **段错误**（2020 年静态链接二进制与新内核不兼容；
   `setarch -R`、gdb 诊断均无效，无 docker）。
3. 改在**云服务器**（内核 5.15）运行 → 全部正常。
4. 自写 `src/celltracker/eval/local_metrics.py::seg_measure`（支持 3D 逐切片金标准），
   与官方基准值逐位比对。

## 观察（自检结果）

| 指标 | 官方文档期望 | 本地实现 | 云端官方二进制 |
| --- | --- | --- | --- |
| SEG seq01 | 0.232874 | **0.232874** ✓ | 0.232874 ✓ |
| SEG seq02 | 0.443686 | **0.443686** ✓ | 0.443686 ✓ |
| DET seq03 | 0.688000 | —（不由本地算） | 0.688000 ✓ |
| TRA seq03 | 0.622980 | —（不由本地算） | 0.622980 ✓ |

四个数全部精确匹配（1e-6 内）。

## 结论

- **本地**：`seg_measure` 可信，且 `tracking_diagnostics`（FN/FP、ID switch、碎片化）
  提供逐帧可迭代的快速反馈。
- **云端**：官方 DET/SEG/TRA 全流程打通（`scripts/cloud_eval.py` 自动上传结果 →
  跑三个官方度量 → 回传指标与官方日志）。所有对外汇报的数字都以此为准。
- 本机无法运行官方二进制这一事实，也是"评测放在云端"这一分工的直接原因。
