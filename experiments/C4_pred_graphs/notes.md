# C4a 用预测检测重建图 + 检测层天花板（误差归属第一级）

## 目的

把检测来源从 GT marker 换成 nnU-Net 预测实例后重建时间展开图，并量化
**"检测层在追踪决策之前就丢掉了多少"**——这是 C4 全链路评测的前置，
也是回答"误差在检测还是在追踪"的第一级漏斗。

## 做了什么

```bash
python scripts/run_pipeline.py --h5 data/interim/Fluo-N3DH-CE_01_pred.h5 \
    --exp-id C4_pred_graphs --dump-graphs data/interim/graphs_01_pred
python scripts/detection_ceiling.py \
    --pred-h5 data/interim/Fluo-N3DH-CE_01_pred.h5 \
    --gt-h5  data/interim/Fluo-N3DH-CE_01.h5 \
    --out experiments/C4_pred_graphs/detection_ceiling.json
```

- 边标签仍由 GT 轨迹 id 生成，预测 h5 通过 `gt_label`（重叠 >50% 的胜者）提供，
  未匹配的检测为 0（=假阳性，自然成为负样本）——训练/测试检测来源一致（R11）。
- 建图 194 对帧，25 秒；OT 规则（未接 GNN）决策后 **2535 条轨迹**
  （GT 检测上界下同一配置是 634–755 条）。

## 观察：检测层天花板（seq01，195 帧）

| 层级 | 含义 | 数值 |
| --- | --- | --- |
| **U0** | GT 节点（marker）在检测集中出现 | **40.7%**（9698 / 23802） |
| **U1** | GT **移动边**两端都被检出 | **25.7%**（5936 / 23082） |
| **U2** | 移动边两端还落在**同一个预测实例**上 | **3.5%**（814 / 23082；占 U1 的 13.7%） |
| **U3** | 分裂的父 + 两子都被检出（且两子在不同实例） | **22.1%**（79 / 358） |

分阶段看：前 50 帧节点检出率 96.6%，后 50 帧只有 **31.8%**（胚胎发育越密越糟）。

## 结论（C4 的核心诊断）

1. **74.3% 的真实移动边在检测层就不存在了**（U1）：这些边无论追踪算法多强都无法恢复，
   在 AOGM 里直接计入缺失边（EA=1.5/条）与缺失节点（FN=10/个）。
2. **实例的跨帧一致性只有 13.7%**（U2/U1）：即使细胞在相邻两帧都被检出，
   代表它的预测实例通常也换了——因为粘连簇每帧被切的方式不同。
   这解释了为什么 GNN 在图上的 move F1 从 0.99 掉到 0.75：
   **训练标签本身随实例 id 漂移**，特征（尺寸/位移/速度）在相邻帧间不连续。
3. 分裂边只有 22.1% 可在检测层观测 → 分裂召回的上限被前端封死
   （GT 检测上界下分裂召回是 0.73–0.80）。

→ 全链路的**主要误差源是检测（实例拆分），不是追踪决策**；C5（实例感知训练目标）
是唯一能把天花板抬起来的改动。这不是"GNN 思路不可行"：GNN 在 GT 检测上贡献
−0.0034（4.9× 噪声地板），只是它无法弥补前端丢掉的质量。
