# C4 对照：预测检测上的匈牙利基线

## 目的

全链路评测需要"同一检测来源下"的对照方法，否则无法区分
"损失来自检测"与"损失来自我们的追踪方法"。

## 做了什么

```bash
python scripts/run_baseline.py --h5 data/interim/Fluo-N3DH-CE_01_pred.h5 \
    --dataset Fluo-N3DH-CE --seq 01 --exp-id C4_pred_hungarian --method hungarian
```

## 观察

| 指标 | 值 |
| --- | --- |
| 检测数/帧 | 50.4（= nnU-Net 预测实例） |
| 轨迹数 | **1116** |
| 本地 ID switch | 7735 |
| 本地碎片化 | 6643 |
| 本地 SEG | 0.6825 |

## 结论

同一检测来源下，匈牙利基线给出 1116 条轨迹；而论文口径 pipeline（OT 规则 2535、
OT+GNN 4682）轨迹数**反而更多**——在"检测只剩 41% 且跨帧不一致"的输入上，
学习型决策没有优势，简单距离匹配更稳。这提示：**在检测质量修好之前，
追踪侧的比较没有意义**（也是 C4 官方数字要同时报三个方法的原因）。
