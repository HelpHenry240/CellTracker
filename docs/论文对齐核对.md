## 2. 逐阶段核对

### 2.1 §1.2 帧内表示：经验测度与邻域图（式 1–7）

#### 式(1) 经验测度的质量

**论文公式**

```
a_i^t = s_i^t / Σ_{k=1}^{n_t} s_k^t ,   μ^t = Σ_i a_i^t · δ_{f_i^t}
```

论文原文："最简单（且与物理直觉一致）的方式是让质量与尺寸成正比。"

**代码位置**：`src/celltracker/cost/features.py::masses`（`features.py:55`）

**核心代码与讲解**

```python
def masses(vol, n, mode="uniform"):
    if mode == "volume" and vol is not None and np.asarray(vol).size == n:
        w = np.maximum(np.asarray(vol, dtype=float), 1e-9)
    else:
        w = np.ones(n, dtype=float)
    return w / w.sum()
```

两种模式都归一到和为 1，对应论文式(1) 与式(3) 的分母归一化。

**⚠️ 区别**：论文取 `mass ∝ 体积`，代码**默认 `mode="uniform"`（等权）**。

依据是 `docs/decisions/0001-mass-uniform-vs-size.md`：CTC 的 `_GT/TRA` 是**等体积标记点**
（实测 358 次分裂中，两子 marker 体积和 / 父 marker 体积 = 恰好 2.00），
所以"质量 ∝ 体积"在 marker 上被解耦、不成立。配套配置项 `measure.mass_mode`
可切回 `"volume"`，留给真实细胞核设定（C8）复核。**论文里必须说明这条偏离。**

#### 式(2)(3) 点级特征

**论文公式**

```
f_i^t = [ x_i^t , s_i^t ] ∈ R^{d+1}
```

**代码位置**：`src/celltracker/track/base.py::Detections`（`base.py:13`）

**核心代码与讲解**

```python
def centroid(self, t: int) -> np.ndarray:
    return np.asarray(self.frames[t]["centroid"], dtype=float)

def volume(self, t: int) -> np.ndarray:
    v = self.frames[t].get("volume")
    return np.asarray(v, dtype=float) if v is not None else np.ones(self.n(t))
```

代码没有把 `f` 拼成一个向量，而是用 `centroid()` / `volume()` 两个统一取值接口分别提供
`x` 与 `s`，下游（代价矩阵、节点特征）按需取用。语义与式(2) 一致。

**✅ 区别**：无实质区别，只是数据结构上拆成两个访问器。

#### 式(4)(5)(6)(7) 帧内图与几何结构

**论文公式**

```
G^t = (V^t, E^t, W^t),  V^t = {1,...,n^t}                              (4)
E^t = { (i,k) | x_k^t ∈ kNN(x_i^t) }                                   (5)
w_ik^t = exp( −‖x_i^t−x_k^t‖² / (2σ_x²) − ‖f_i^t−f_k^t‖² / (2σ_f²) )   (6)
D_ik^t = ‖x_i^t − x_k^t‖₂                                              (7)
```

**代码位置**：`src/celltracker/cost/features.py::gaussian_knn_graph`（`features.py:64`）

**核心代码与讲解**

```python
    order = np.argsort(D_full, axis=1)
    mask = np.zeros((n, n), dtype=bool)
    rows = np.repeat(np.arange(n), k_eff)
    cols = order[:, 1:k_eff + 1].reshape(-1)
    mask[rows, cols] = True
    mask = mask | mask.T                    # 对称化

    D = np.where(mask, D_full, 0.0)         # 式(7)：非邻接处置 0
    sx = sigma_x if sigma_x is not None else float(np.median(D_full[D_full > 0]) + 1e-9)
    W = np.exp(-D_full ** 2 / (2 * sx ** 2))                # 式(6) 空间项
    if feat is not None and sigma_f is not None:
        Df = pairwise_distance(feat, feat)
        W = W * np.exp(-Df ** 2 / (2 * sigma_f ** 2))       # 式(6) 特征项
    W = np.where(mask, W, 0.0)
    return D, W
```

讲解：

1. **式(5)**：用 `argsort` 取每行最近的 `k` 个（跳过自身），再对称化，得到无向 kNN 邻接；
2. **式(7)**：`D` 是全对欧氏距离，但只保留邻接项，非邻接处置 0——0 在结构项里等价于"无贡献"；
3. **式(6)**：`W` 按高斯核构造，`σ_x` 缺省时用"正距离中位数"自适应（论文未规定 `σ_x` 取值）。

**⚠️ 区别 1（式(7)）**：论文定义 `D_ik = ‖x_i−x_k‖₂` 对**所有** `i,k∈V^t` 成立（全对矩阵）；
代码是 **kNN 截断**版本。论文 §1.7 明确允许"结合稀疏邻接（有限度地截断 `D^t`）来降低复杂度"，
故属允许的近似，但与式(7) 字面不同。

**❌ 区别 2（式(6)）：`W` 是死代码，特征项从未生效。**

`gaussian_knn_graph` 返回 `(D, W)`，但**全部调用点都写成 `D, _ = ...`，把 `W` 丢弃**：

| 调用点 | 代码 |
| --- | --- |
| `pipeline/ot_stage.py:99,101` | `D, _ = gaussian_knn_graph(...)` |
| `graph/build.py:227` | `D, _ = gaussian_knn_graph(...)` |

同时 `feat` 与 `sigma_f` 这两个参数**没有任何调用者传入**，配置项
`measure.sigma_f`（`pipeline/config.py:40`）也没有消费者。
结果是式(6) 的**特征相似度项 `exp(−‖f_i−f_k‖²/2σ_f²)` 完全没参与计算**，
链路实际只用到了 `D`。这一条在 `docs/pipeline_code_map.md` 中没有记录。

### 2.2 §1.3 相邻帧最优传输（式 8–14）

#### 式(8) 特征代价 + R_max 门限

**论文公式**

```
C_feat_ij = α‖x_i^t − x_j^{t+1}‖₂² + β( (s_i^t − s_j^{t+1}) / σ_s )²
‖x_i^t − x_j^{t+1}‖₂ > R_max ⇒ C_feat_ij = +∞
```

**代码位置**：`src/celltracker/cost/features.py::build_cost`（`features.py:29`）

**核心代码与讲解**

```python
    d_cur = pairwise_distance(src_xy, dst_xy)
    C = cfg.alpha * d_cur ** 2                                  # α 项（式8）

    if cfg.alpha_pred > 0 and pred_xy is not None:               # α′ 项（式22）
        d_pred = pairwise_distance(pred_xy, dst_xy)
        C = C + cfg.alpha_pred * d_pred ** 2

    if cfg.beta > 0 and src_vol is not None and dst_vol is not None:
        scale = cfg.sigma_s * max(float(np.mean(s_dst)), 1e-9)   # β 项（式8）
        C = C + cfg.beta * ((s_src[:, None] - s_dst[None, :]) / scale) ** 2

    C = np.where(d_cur <= cfg.r_max, C, np.inf)                  # R_max 门限
```

讲解：三段分别对应式(8) 的位移项、式(22) 的运动先验项、式(8) 的尺寸项；
最后一行把超出 `R_max` 的配对置 `+∞`，与论文"在成本层面排除位移明显不合理的匹配"一致。

**⚠️ 区别 1（β）**：论文写 `α,β > 0`，代码**默认 `β=0`（尺寸项关闭）**，
见 `OTConfig.beta`（`pipeline/config.py:57`）。默认配置下式(8) 只剩位移项。

**⚠️ 区别 2（σ_s 用法）**：论文的归一化是 `(s_i−s_j)/σ_s`，代码是
`(s_i−s_j)/(σ_s · mean(s_dst))`，即额外乘了一个"目标帧平均尺寸"做量纲缩放。
属工程上的量纲处理，但改写了归一化分母。

#### 式(9) FGW 结构项

**论文公式**

```
L(Γ) = (1−η) Σ_{i,j} C_feat_ij Γ_ij
     + η Σ_{i,k} Σ_{j,ℓ} ( D_ik^t − D_jℓ^{t+1} )² Γ_ij Γ_kℓ
```

**代码位置**：`src/celltracker/ot/fgw.py::structural_term`（`fgw.py:22`）、
`structural_grad`（`fgw.py:30`）、`fused_gw`（`fgw.py:45`）

**核心代码与讲解**

```python
def structural_term(P, D, Dp):
    r = P.sum(axis=1)          # 行和
    c = P.sum(axis=0)          # 列和
    return float(r @ ((D * D) @ r)
                 + c @ ((Dp * Dp) @ c)
                 - 2.0 * np.sum(P * (D @ P @ Dp)))
```

讲解：论文式(9) 的四重和 `Σ_{i,k,j,ℓ}` 在最坏情况下是 `O(n²m²)`。
代码用矩阵恒等式把它化简为

```
Σ (D_ik − D'_jℓ)² Γ_ij Γ_kℓ = rᵀ(D∘D)r + cᵀ(D'∘D')c − 2⟨P, D P D'⟩
```

其中 `r = P1`、`c = Pᵀ1`。这**不是近似**，是同一式子的等价矩阵形式，
把复杂度降到矩阵乘法级别。`fused_gw` 用条件梯度（Frank–Wolfe）+ Sinkhorn 线性 oracle 求解。

**✅ 区别**：无。梯度也经有限差分校验（`tests/test_fgw.py`）。

#### 式(10)(11)(12) 平衡熵正则 OT

**论文公式**

```
Σ_j Γ_ij = a_i^t ,  Σ_i Γ_ij = a_j^{t+1}            (10)
Ent(Γ) = Σ_{i,j} Γ_ij ( log Γ_ij − 1 )                (11)
min_{Γ≥0} L(Γ) + ε Ent(Γ)
   s.t.  Γ1 = a^t ,  Γᵀ1 = a^{t+1}                    (12)
```

**代码位置**：`src/celltracker/ot/sinkhorn.py::sinkhorn_log`（`sinkhorn.py:34`）

**核心代码与讲解**

```python
    lam_a = 1.0 if tau_a is None else tau_a / (tau_a + eps)
    lam_b = 1.0 if tau_b is None else tau_b / (tau_b + eps)
    ...
    for it in range(n_iter):
        f = lam_a * eps * (log_a - _lse((g[None, :] - C_eff) / eps, axis=1))
        g = lam_b * eps * (log_b - _lse((f[:, None] - C_eff) / eps, axis=0))
```

讲解：这是 log-domain Sinkhorn 的不动点迭代。当 `tau_a = tau_b = None` 时
`lam_a = lam_b = 1`（硬边际约束），退化为式(12) 的平衡 OT。
`KL(P|K)`（`K = exp(−C/ε)`）与论文式(11) 的 `Ent(Γ)` 只差常数：

```
ε·KL(P ‖ exp(−C/ε)) = ⟨P,C⟩ + ε Σ P(log P − 1) + const
```

故与 "`L(Γ) + ε Ent(Γ)`" 等价。平衡情形额外检查边际违反量 `tol_marg`，
避免"对偶变量收敛但边际仍差 1e-5"的伪收敛。

**⚠️ 区别（ε）**：论文取固定 `ε > 0`；代码**默认用 `ε = ε_rel × median(C)` 自适应**
（`eps_rel=0.1`，见 `ot_stage.py` 的 `eps_eff` 计算）。

理由（`ot_stage.py` 模块 docstring 与 `AGENTS.md` R3）：`C` 是平方距离，
CE 数据中位数量级约 `4×10²`；直接取 `ε=1` 会让传输计划退化成硬分配，
实测真实分裂边的传输质量直接为 0，失去 §1.3 "软匹配"的前提。
这是 🔧 **工程补充**，论文里必须标注。

#### 式(13)(14) 非平衡 OT（KL 松弛）

**论文公式**

```
KL(u‖v) = Σ_i u_i log(u_i/v_i) − u_i + v_i                             (13)
min_{Γ≥0} L(Γ) + ε Ent(Γ)
   + τ_t KL( Γ1 ‖ a^t ) + τ_{t+1} KL( Γᵀ1 ‖ a^{t+1} )                 (14)
```

论文说明：`τ→∞` 逼近平衡 OT；`τ` 较小时允许大规模出生/死亡/分裂。

**代码位置**：同上（`sinkhorn.py::sinkhorn_log` 的 `tau_a` / `tau_b`）

**核心代码与讲解**

```python
def sinkhorn_log(C, a, b, eps=0.05, tau_a=None, tau_b=None, ...):
```

讲解：`tau_a`/`tau_b` 即论文的 `τ_t`/`τ_{t+1}`。标准非平衡 Sinkhorn 的缩放因子为
`λ = τ/(τ+ε)`，代码里 `lam_a`/`lam_b` 正是这个式子，因此是式(14) 的正确不动点形式。
配置默认 `tau_a = tau_b = None`（平衡），对应论文"τ→∞ 逼近平衡 OT"的极限。

**✅ 区别**：无。语义（`τ` 小 → 更多出生/死亡/分裂）与论文一致。

### 2.3 §1.4 时序网络关联与多尺度时间正则（式 15–19）

#### 式(15)(16) 时间展开网络

**论文公式**

```
V = ∪_{t=1}^{T} { (i,t) | i ∈ V^t }                                    (15)
E_inter = ∪_{t=1}^{T−1} { (i,t)→(j,t+1) | Γ_ij^t > 0 }                 (16)
```

**代码位置**：`src/celltracker/graph/build.py::build_pair_graph`（`build.py:102`）；
全局串联在 `pipeline/runner.py`。

**核心代码与讲解**

```python
    if cfg.cand_from_ot and plan is not None:
        row_sum = plan.sum(axis=1, keepdims=True) + 1e-12
        rnorm_full = plan / row_sum
        mask = (rnorm_full >= cfg.theta_gamma) & finite
        ...
        ii, jj = np.where(mask)
    pairs = np.stack([ii, jj], axis=1)
```

讲解：代码不构造一张全局大图，而是**逐对相邻帧**构造小图 (`pair_XXXX.npz`)，
再在 `gnn/infer.py::reconstruct_tracks` 里按时间串联成轨迹。
边的支撑来自 OT 计划的支撑（式16），并加了 `θ_Γ` 门限。

**⚠️ 区别**：论文把 `V, E_inter` 定义为一个统一的时间展开网络；
代码是"逐对帧的图 + 按时间串联"。数学上等价（`E_inter` 本身就是各帧对的并集），
但实现上不是一个整体对象，且候选边比"`Γ>0` 的支撑"更窄（多了 θ_Γ / θ_C 门限，见式26）。

#### 式(17)(18)(19) 全局目标与多尺度时间一致性

**论文公式**

```
min_{ {Γ^t} } Σ_{t=1}^{T−1} [ L(Γ^t) + ε Ent(Γ^t) + τ_t KL(Γ^t1‖a^t) + τ_{t+1} KL((Γ^t)ᵀ1‖a^{t+1}) ]
            + λ_temp Σ_{t=1}^{T−2} R_temp(Γ^t, Γ^{t+1})                        (17)

R_temp(Γ^t, Γ^{t+1}) = ‖ Γ^{t,t+2}_direct − Γ^t Γ^{t+1} ‖_F²                  (18)

R^(k)_temp(Γ^t,…,Γ^{t+k−1}) = ‖ Γ^{t,t+k}_direct − Γ^t Γ^{t+1} ⋯ Γ^{t+k−1} ‖_F²   (19)

附加 Σ_{k∈K} λ^(k)_temp Σ_t R^(k)_temp ,   K 如 {2,3,5}
```

**代码位置**：

- `src/celltracker/ot/multiscale.py::direct_jump_coupling`（`multiscale.py:31`）→ 式(19) 的 `Γ^{t,t+k}_direct`
- `src/celltracker/ot/multiscale.py::temporal_regularizer`（`multiscale.py:54`）→ 式(19)
- `src/celltracker/pipeline/multiscale_stage.py::refine_couplings`（`multiscale_stage.py:48`）→ 式(17) 的阶段实现

**核心代码与讲解**

条件概率归一化（对应论文式17 下方的 Markov 定义）：

```python

        """行归一化为条件概率（式17 下方的定义）。"""
        return M / (M.sum(axis=1, keepdims=True) + 1e-12)
```

正则值（式18/19 的加权和）：

```python
    def _reg_value(P_cur):
        total = 0.0
        for (i, k), D in direct.items():
            idxs = list(range(i, i + k))
            out = _cond(P_cur[idxs[0]])
            for j in idxs[1:]:
                out = out @ _cond(P_cur[j])
            total += lam_ks[k] * float(np.sum((_cond(D) - out) ** 2))
        return total
```

求解策略（交替优化 + 回溯线搜索）：

```python

        reg_before = _reg_value(P)
        step = float(cfg.lambda_temp)
        for _attempt in range(5):
            cand = _gauss_seidel_once(P, step)
            reg_cand = _reg_value(cand)
            if reg_cand <= reg_before:
                best_P, best_reg = cand, reg_cand
                break
            step *= 0.5                     # 回溯半砍，保证正则单调不增

```

单轮 Gauss–Seidel 更新：对每对帧用"基础代价 + λ·∂R/∂Γ"重解 Sinkhorn：

```python

            out[i] = sinkhorn_log(G, a_i, b_i, eps=eps_eff[i],
                                  tau_a=ot_cfg.tau_a, tau_b=ot_cfg.tau_b)
```

讲解：式(17) 是一个关于全部 `{Γ^t}` 的联合优化问题。代码没有直接做联合优化，
而是采用论文 §1.7 建议的**交替优化**：先用相邻帧独立解初始化，
再按时序正则的梯度对每个 `Γ^t` 做少量重解，并加回溯线搜索防止发散。

**⚠️ 区别 1（联合优化 → 交替近似）**：论文式(17) 是统一的 `min over {Γ_t}`，
代码是 Gauss–Seidel 交替近似，不是精确联合解。

**⚠️ 区别 2（条件概率）**：式(18)(19) 字面上比较的是**原始乘积** `Γ^t Γ^{t+1}`；
代码在比较前对每个 `Γ` 做**行归一化** `_cond`。

依据（`multiscale_stage.py::_cond` docstring）：`Γ` 的行和是质量 `a^t ≈ 1/n`，
两个 `Γ` 相乘会把质量平方（实测 `D` 的行和 `1/43`，而 `Γ_tΓ_{t+1}` 的行和 `≈ (1/43)²`），
直接相减等于拿两个不同质量尺度的量比较，式(18) 就失去意义。
论文 §1.4 本身也给出了条件概率 `P((j,t+1)|(i,t)) = Γ_ij / (Σ_j' Γ_ij' + δ)` 的定义，
所以在该空间复合是合理的。**属有依据偏离，论文中需说明。**

**⚠️ 区别 3（时间尺度权重）**：论文是**逐尺度**权重 `λ^(k)_temp`；
代码所有 `k` 共用一个 `lambda_temp`：

```python

```

**⚠️ 区别 4（跳帧 OT 的求法）**：论文建议 `Γ^{t,t+k}_direct` "可以在下采样的空间网格
或抽样子集上求解，以控制计算复杂度"；代码在**全分辨率**上求解，只把候选半径按 gap 放宽：

```python

    art = compute_pairwise_plan(src_xy, dst_xy, jump_cfg,
                                measure=MeasureConfig(mass_mode="uniform"))
```

注意这里 **硬编码 `mass_mode="uniform"`**，与 pipeline 的 `measure.mass_mode` 配置脱钩。
当前默认就是 uniform，无实际影响；但若切到 `"volume"`，相邻帧 OT 与跳帧 OT 会口径不一致。

#### 式(30)(31)(32) 边–节点交替消息传递

**论文公式**

```
e^(l+1)_{u→v} = φ_e( e^(l)_{u→v}, h^(l)_u, h^(l)_v )     (30)
m̃^(l+1)_v = Σ_{(u→v)∈E} e^(l+1)_{u→v}                    (31)
h^(l+1)_v = φ_h( h^(l)_v, m̃^(l+1)_v )                     (32)
```

**代码位置**：`src/celltracker/gnn/model.py::EdgeGNN.forward`（`model.py:59`）

**核心代码与讲解**

```python
        h = self.node_enc(node_feat)
        e = self.edge_enc(edge_feat)
        u, v = edge_index[0], edge_index[1]
        for edge_mlp, node_mlp in zip(self.edge_updates, self.node_updates):
            msg = torch.cat([e, h[u], h[v]], dim=-1)
            e = e + edge_mlp(msg)                          # 式(30)
            agg = torch.zeros_like(h)
            agg.index_add_(0, v, e)                        # 式(31)：按目标节点聚合
            h = h + node_mlp(torch.cat([h, agg], dim=-1))  # 式(32)
        return self.edge_head(e)
```

逐行对应：`msg = [e, h_u, h_v]` 是式(30) 的 `φ_e` 输入；
`index_add_(0, v, e)` 把边嵌入按目标节点 `v` 求和，即式(31)；
`node_mlp([h, agg])` 是式(32) 的 `φ_h`。

**⚠️ 区别（残差连接）**：论文式(30)(32) 是 `e' = φ_e(...)`、`h' = φ_h(...)` 的纯映射；
代码写成了 `e = e + φ_e(...)`、`h = h + φ_h(...)`（残差）。属实现细节，
形式上仍是 `φ_e/φ_h` 的输出，不影响公式结构，但论文若逐式对照需说明。
